# Domain docs

This repo uses a single context: `GLOSSARY.md` at the root and `docs/adr/` for architectural decisions.

## Before exploring

Read `GLOSSARY.md` when it exists. Read ADRs in `docs/adr/` that concern the area being explored.

If these files are absent, proceed. Domain modeling creates them when terms or decisions are resolved.

## Vocabulary

Use the glossary's canonical terms in issue titles, explanations, hypotheses, and code. When a needed concept is missing, raise it during domain modeling.

## Decision conflicts

If a proposal contradicts an existing ADR, identify that ADR and explain why the decision should be reconsidered.
