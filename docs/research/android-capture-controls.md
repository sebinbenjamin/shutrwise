# Android capture controls and measurement gaps

Research date: 2026-10-06. Scope: public Android APIs available to an ordinary third-party camera app, with Galaxy S25 Ultra as the device to measure. No phone, firmware dump, sample capture, or benchmark was available. Every S25 Ultra capability below remains unverified. This note records API contracts and proposed measurements, not an app architecture.

Android offers enough public control to investigate source-preserving exposure capture. It does not establish that this exact phone exposes every lens, a 200 MP RAW stream, or Samsung Camera/Expert RAW processing through those APIs. Android's own multi-camera guide explains that manufacturers' camera apps can use private APIs or special driver treatment. Public API access does not imply equivalent results. [Android multi-camera guide](https://developer.android.com/media/camera/camera2/multi-camera)

## What Android can promise

Promises attach to the capabilities advertised by each camera ID, not the phone's product name. `MANUAL_SENSOR` covers exposure time, sensitivity, frame duration, adjustable lens controls, and supported flash controls. `MANUAL_POST_PROCESSING` is separate. `RAW` guarantees `RAW_SENSOR` output and DNG interpretation metadata; RAW and manual sensor control are distinct capabilities. [Camera capability contracts](https://developer.android.com/reference/android/hardware/camera2/CameraMetadata#REQUEST_AVAILABLE_CAPABILITIES_MANUAL_SENSOR)

For a conventional manual exposure request, disable AE and set `SENSOR_EXPOSURE_TIME`, `SENSOR_SENSITIVITY`, and `SENSOR_FRAME_DURATION` within reported limits. AE normally overrides these values. Exposure time can round down to the closest supported duration; read the actual capture result. Frame duration is bounded by the stream configuration and exposure plus overhead. Newer AE priority controls are optional and must be queried before using them. [Capture request controls](https://developer.android.com/reference/kotlin/android/hardware/camera2/CaptureRequest#SENSOR_EXPOSURE_TIME)

`TotalCaptureResult` describes the final settings applied to a capture. Keep requested settings and reported settings separately. For requested physical-camera streams, `getPhysicalCameraTotalResults()` supplies the corresponding physical results; a logical-only capture does not automatically include them. [Total capture results](https://developer.android.com/reference/android/hardware/camera2/TotalCaptureResult)

`SENSOR_TIMESTAMP` marks the first sensor row's exposure start and matches the image buffers from that capture. Use it to associate images with results, alongside camera ID and frame number. `UNKNOWN` timestamp sources allow comparisons within the same camera; `REALTIME` allows comparison with `elapsedRealtimeNanos()`. Callback arrival time measures delivery, not exposure start. [Capture timestamps](https://developer.android.com/reference/android/hardware/camera2/CaptureResult#SENSOR_TIMESTAMP)

## RAW and DNG boundaries

`RAW_SENSOR` ordinarily represents a mosaic of sensor samples stored in 16-bit values. The camera defines the mosaic layout, encoding range, and color interpretation. That storage width does not prove 16 bits of useful sensor precision, nor does the format name prove a 200 MP ordinary Bayer array. [RAW_SENSOR format](https://developer.android.com/reference/android/graphics/ImageFormat#RAW_SENSOR)

Check both the normal stream map and, when exposed, `SCALER_STREAM_CONFIGURATION_MAP_MAXIMUM_RESOLUTION`. The latter describes captures using `SENSOR_PIXEL_MODE_MAXIMUM_RESOLUTION`; an advertised JPEG size is not evidence for the same RAW size. Each map supplies supported format/size pairs. [Maximum resolution stream map](https://developer.android.com/reference/android/hardware/camera2/CameraCharacteristics#SCALER_STREAM_CONFIGURATION_MAP_MAXIMUM_RESOLUTION)

Ultra-high-resolution cameras can expose binning and remosaic behavior. `REMOSAIC_REPROCESSING` describes grouped-color RAW conversion; RAW captured alongside non-RAW output has a regular Bayer pattern under that capability's documented conditions. Thus RAW-only and RAW+JPEG need separate inspection. Logical camera switches can also change exposure and lens properties despite AE/AF locks. [Remosaic contract](https://developer.android.com/reference/android/hardware/camera2/CameraMetadata#REQUEST_AVAILABLE_CAPABILITIES_REMOSAIC_REPROCESSING), [manual sensor contract](https://developer.android.com/reference/android/hardware/camera2/CameraMetadata#REQUEST_AVAILABLE_CAPABILITIES_MANUAL_SENSOR)

`DngCreator` writes `RAW_SENSOR` pixels using camera characteristics and capture metadata. Missing metadata can make writing fail. Preserve the metadata that belongs to that image and test the resulting DNG in an independent reader. A DNG wrapper records captured data; it does not certify Samsung processing equivalence. [DNG writer](https://developer.android.com/reference/android/hardware/camera2/DngCreator)

## Camera selection and exposure bursts

A logical camera groups physical cameras and may return a selected or fused image. Query its physical IDs rather than assigning lenses by assumed numeric IDs. Physical output selection uses `OutputConfiguration.setPhysicalCameraId`; independently adjustable physical request keys come from `getAvailablePhysicalCameraRequestKeys()`. Log active physical ID when reported and verify the desired lens actually supplied the capture. [Logical and physical cameras](https://developer.android.com/media/camera/camera2/multi-camera), [physical request keys](https://developer.android.com/reference/android/hardware/camera2/CameraCharacteristics#getAvailablePhysicalCameraRequestKeys()), [active physical ID](https://developer.android.com/reference/android/hardware/camera2/CaptureResult#LOGICAL_MULTI_CAMERA_ACTIVE_PHYSICAL_ID)

Supported formats and sizes do not prove that a proposed preview+RAW+JPEG or multi-camera combination will work. Match the documented stream combinations and query session support where available, then create and exercise the session. Physical stream combinations need their own validation. [Session combinations](https://developer.android.com/reference/android/hardware/camera2/CameraDevice#createCaptureSession(android.hardware.camera2.params.SessionConfiguration))

`captureBurst` submits an ordered list of capture requests without other capture/repeating requests interspersed. This supports exposure brackets with different settings per request. It promises the minimum achievable duration, not a chosen fixed interval, simultaneous exposures, motion-free registration, or a successful saved image for every request. [Burst submission](https://developer.android.com/reference/android/hardware/camera2/CameraCaptureSession#captureBurst(java.util.List,%20android.hardware.camera2.CameraCaptureSession.CaptureCallback,%20android.os.Handler))

`BURST_CAPTURE` describes specified high-resolution YUV throughput under suitable processing settings. It is not a guarantee for maximum-resolution RAW+JPEG throughput. [Burst capability](https://developer.android.com/reference/android/hardware/camera2/CameraMetadata#REQUEST_AVAILABLE_CAPABILITIES_BURST_CAPTURE)

Use `getOutputMinFrameDuration` and `getOutputStallDuration` to estimate format/size timing. RAW and JPEG can stall; high-quality processing can make stall timing indeterminate. Exposure duration, the configured streams, outstanding buffers, and saving work still constrain real cadence. Measure exposure timestamps and completed files instead of promising a burst rate from a sensor specification. [Stream timing](https://developer.android.com/reference/android/hardware/camera2/params/StreamConfigurationMap#getOutputStallDuration(int,%20android.util.Size))

## CameraX, Camera2, and vendor extensions

CameraX provides lifecycle management and common capture use cases. Since 1.5.0, `ImageCapture` supports RAW and simultaneous RAW+JPEG; query supported output formats for the selected camera. This API capability does not confirm that the S25 Ultra supports the desired stream combination. RAW+JPEG callbacks need not arrive in a fixed order. Therefore RAW alone is not a reason to exclude CameraX. [CameraX architecture](https://developer.android.com/media/camera/camerax/architecture), [ImageCapture formats](https://developer.android.com/reference/androidx/camera/core/ImageCapture#OUTPUT_FORMAT_RAW_JPEG), [output format query](https://developer.android.com/reference/androidx/camera/core/ImageCaptureCapabilities#getSupportedOutputFormats())

CameraX Camera2 interop can override capture keys, but the documented override can interfere with CameraX controls and 3A behavior. My recommendation is to use direct Camera2 for the measurement probe and ordered exposure-bracket experiment, then assess whether CameraX meets the actual app requirements. This is a recommendation about controllability and observability, not a claim that CameraX lacks RAW. [Camera2 interop](https://developer.android.com/reference/androidx/camera/camera2/interop/Camera2Interop.Extender#setCaptureRequestOption(android.hardware.camera2.CaptureRequest.Key,%20java.lang.Object))

Both APIs offer vendor extensions such as Night and HDR when the selected camera supports them. They can combine several input frames into one processed output. Query extension-specific sizes, request keys, result keys, and latency estimates separately from ordinary sessions. The public contract does not promise delivery of all input frames, so an extension cannot satisfy source-frame preservation without further evidence. Nor does an extension name promise Samsung's first-party output. [Camera extensions](https://developer.android.com/media/camera/camera-extensions), [extension characteristics](https://developer.android.com/reference/android/hardware/camera2/CameraExtensionCharacteristics)

## Capability probe on the exact S25 Ultra

The following is a proposed measurement checklist. Record failures and absent keys as results; do not infer support from another phone's report.

1. Record model/region, Android and One UI versions, build fingerprint, app target SDK, and camera library versions. Save a timestamped report so a firmware update can be retested.
2. Enumerate public camera IDs, physical IDs, lens facing/focal lengths, hardware level, capability flags, and available characteristics/request/result/physical-request keys. Record exposure and sensitivity ranges, maximum analog sensitivity, maximum frame duration, focus limits, AE/AF/AWB modes and locks. [Characteristics queries](https://developer.android.com/reference/android/hardware/camera2/CameraCharacteristics)
3. Export normal, high-resolution, and maximum-resolution output sizes for RAW, JPEG, and YUV, with minimum durations and stalls. Record pixel/active arrays, CFA, binning factor where present, black/white levels, color transforms, and timestamp source. Check proposed sessions with preview, RAW-only, RAW+JPEG, and any selected physical camera. [Stream maps](https://developer.android.com/reference/android/hardware/camera2/params/StreamConfigurationMap), [session support](https://developer.android.com/reference/android/hardware/camera2/CameraDevice#isSessionConfigurationSupported(android.hardware.camera2.params.SessionConfiguration))
4. Capture static lit, dark, and flat-field scenes across a few in-range shutter/ISO settings. Compare requested versus returned exposure, ISO, focus, crop, pixel mode, processing modes, and active physical camera. Inspect saved RAW dimensions, CFA, black/white levels, and visible artifacts. Compare RAW-only with RAW+JPEG. Confirm DNG writing and independent decoding before calling a mode supported. This tests usable data, not just advertised metadata.
5. Submit a small ordered bracket and a repeated-exposure burst with focus and white balance held where supported. Record every request, result, image timestamp, frame number, capture failure, missing buffer, and successfully saved file. Measure exposure-start intervals separately from delivery and save latency. Repeat with preview active, different RAW sizes, longer exposures, and sustained use; report distributions and thermal state rather than a single best rate.
6. Drain source captures with `acquireNextImage()` and close images after saving/copying. `acquireLatestImage()` discards older queued frames; unreleased images exhaust the queue. Test a deliberately slow saver and an interrupted sequence to establish how the app reports incomplete captures. [ImageReader queue behavior](https://developer.android.com/reference/android/media/ImageReader#acquireNextImage())
7. Query and exercise each available extension and CameraX RAW/RAW+JPEG mode. Compare its formats, metadata, capture latency, and source access with ordinary Camera2 captures. CameraX output formats can change when extensions are enabled. [CameraX output configuration](https://developer.android.com/reference/androidx/camera/core/ImageCapture.Builder#setOutputFormat(int))

The unresolved device facts are accessible lenses, RAW resolution and sample structure for each mode, accepted stream combinations, actual exposure limits and rounding, metadata completeness, burst reliability under storage/thermal load, and extension behavior. This research closes the API question only. It cannot close those measurements.

## Practical implications for a beginner camera app

Keep automatic capture and plain exposure advice usable first. Offer manual controls only when supported, show the setting actually used, and explain when longer exposure requires holding still. Gate RAW and bracketing on successful device probes; do not advertise 200 MP RAW or first-party Samsung parity.

Preserve each source capture as its own file and retain its provenance: capture group, intended exposure, applied settings, camera/physical ID, timestamps, format, size, and completion state. Save a companion JPEG when the measured session supports it. Any later merged or edited image should be a separate derivative. A missing burst frame must leave an explicitly incomplete group, not a quietly fabricated success. These are product recommendations drawn from the capture and queue contracts above.
